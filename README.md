# 🔗 short.steins.ru

Сервис для быстрой и безопасной передачи ссылок со смартфона на компьютер в аудитории (с защитой через ручное подтверждение на экране компьютера) + автономный 24-часовой URL-сокращатель.

## 💡 Сценарий использования (Компьютер в аудитории + Телефон)

1. На компьютере/проекторе открывается **short.steins.ru**.
2. Экран автоматически генерирует сессию и показывает **QR-код**.
3. Преподаватель наводит стандартную камеру смартфона на QR-код и переходит по ссылке.
4. На смартфоне открывается простая форма: вставляется ссылка и нажимается «Отправить на компьютер».
5. Сервер мгновенно передает ссылку на экран через WebSocket.
6. На проекторе отображается карточка входящей ссылки: оригинальный адрес, короткий URL и кнопки «Открыть в новой вкладке» / «Отклонить».
7. Преподаватель визуально проверяет адрес и подтверждает открытие кликом за компьютером.

> **Безопасность:** Студенты в аудитории не могут принудительно вывести нежелательный контент на проектор — любая отправленная ссылка требует физического подтверждения кликом на компьютере докладчика.

## 🛠 Стек технологий

- **Backend:** Go (net/http, Gorilla WebSocket), SQLite (`modernc.org/sqlite` — чистый Go, без CGO).
- **Frontend:** Bun, React 18, TypeScript, Tailwind CSS, Vite.
- **Инструменты автоматизации:** Taskfile (`task`), Air (hot reload), ESLint, GolangCI-Lint.
- **Контейнеризация:** Multi-stage Dockerfile (Bun → Go embed → Alpine minimal).
- **Reverse-Proxy:** Traefik с автоматическими Let's Encrypt TLS-сертификатами.
- **CI/CD:** GitHub Actions (линтеры, тесты, сборка образа в `ghcr.io` и деплой по SSH).

## ⚡ Taskfile команды

Управление проектом осуществляется через `task`:

```bash
task dev            # Сборка фронтенда и запуск Go-сервера с hot-reload (Air)
task build          # Сборка фронтенда (Bun) и бинарника Go (bin/short)
task lint           # Запуск линтеров: golangci-lint и eslint
task test           # Запуск всех тестов: go test и bun test
task test:perf      # Запуск стресс- и latency-тестов высокой конкурентности
task bench          # Запуск Go benchmarks с замером аллокаций памяти (-benchmem)
task docker:build   # Сборка multi-stage Docker-образа
task docker:push    # Пуш Docker-образа в ghcr.io
```

## ⚙️ Переменные окружения (ENV)

| Переменная | По умолчанию | Описание |
|-----------|-------------|---------|
| `BASE_URL` | `http://localhost:8080` | Базовый публичный адрес сервера для генерации ссылок и QR |
| `PORT` | `8080` | Порт HTTP-сервера |
| `DB_PATH` | `./data/short.db` | Путь к файлу базы данных SQLite |

## 🚀 Деплой (VPS + Traefik)

### Необходимые Secrets в GitHub репозитории

| Secret | Описание |
|--------|----------|
| `VPS_HOST` | IP-адрес или домен VPS |
| `VPS_USER` | Пользователь SSH (например, `deployer`) |
| `VPS_SSH_KEY` | Приватный SSH-ключ для авторизации |

> `GITHUB_TOKEN` генерируется автоматически для публикации в GitHub Container Registry (`ghcr.io`).

### Первоначальный запуск на сервере

```bash
ssh deployer@<VPS>
mkdir -p ~/short
# Скопируйте docker-compose.yml в ~/short/
cd ~/short
docker compose pull && docker compose up -d
```

### Автоматический CI/CD

- При создании **Pull Request** или **Push** в любую ветку срабатывает `.github/workflows/ci.yml`: проверка линтерами (`golangci-lint`, `eslint`), запуск тестов Go и тестов Bun, тестовая сборка.
- При мерже в **main** срабатывает `.github/workflows/deploy.yml`: сборка Docker-образа, публикация в `ghcr.io` и автоматическое обновление контейнера на VPS по SSH.
